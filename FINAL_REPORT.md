# ClinSynth — Final Report

**SH-405: Synthetic Patient Data Generation for Clinical Research**

---

## 1. What Was Built

ClinSynth: an advanced privacy-aware clinical cohort simulation and validation platform with a production-style FastAPI + Next.js architecture (12 pages) and an optional legacy Streamlit UI. The system loads patient data, trains synthetic data generators, compares models, builds custom cohorts with nested/conditional constraints, generates longitudinal health journeys with trajectory archetypes, validates data statistically at per-column and subgroup levels, screens for privacy leakage with real-to-real baseline context, explores privacy-vs-fidelity tradeoffs, manages experiment history, and exports comprehensive results.

## 2. Architecture

```
Data Ingestion -> Preprocessing -> Plausibility Guardrails
  -> SDV Synthesizer Training (CTGAN / Gaussian Copula)
  -> Model Comparison Lab (optional, side-by-side evaluation)
  -> Sample Generation -> Cohort Builder (nested/conditional constraints)
  -> Privacy Mode Filtering (low/balanced/high: rejection + noise)
  -> Plausibility Repair -> Temporal Engine (trajectory archetypes)
  -> Longitudinal Guardrails -> Statistical Validation
    (per-column quality cards, subgroup fidelity, pairwise correlations)
  -> Privacy Screening (real-to-real baseline, synth-to-synth, NN analysis)
  -> Experiment History (JSON-based) -> FastAPI REST API -> Next.js Frontend (12 pages)
  -> Comprehensive CSV/JSON/ZIP Export with Quality Report
```

**Primary UI**: Next.js 16 (TypeScript, Tailwind CSS, Recharts) + FastAPI backend
**Legacy UI**: Streamlit 12-page dashboard (app.py, optional)

Modular structure under `src/` with 9 core subpackages: data, preprocessing (+ guardrails), synthesis (+ comparison), cohort, temporal, validation, privacy, visualization, utils (+ experiments). Backend under `backend/` (FastAPI routes, Pydantic schemas, state management). Frontend under `frontend/` (Next.js App Router, TypeScript API client).

## 3. Dataset Used

Deterministic bundled demo dataset generated by `src/data/demo_generator.py`. All records are purely synthetic sample data with realistic clinical relationships built in (age-BP correlation, diabetes/hypertension subgroups, activity variation).

## 4. Dataset Size

- 500 demo patients (profiles)
- 15,000 longitudinal records (30 days x 500 patients)

## 5. Models Used

SDV library synthesizers:
- **CTGANSynthesizer**: Deep learning-based, learns complex relationships
- **GaussianCopulaSynthesizer**: Statistical copula-based, fast and stable

Both are fitted on the source dataset — they are not pretrained healthcare models. The Model Comparison Lab trains and evaluates both side-by-side on fidelity, privacy, training time, generation time, and model size.

## 6. Model Training Configuration

- CTGAN: configurable epochs (default 50 demo / 150 standard / 300 high quality), batch size 500
- Gaussian Copula: no epoch configuration needed
- Automatic fallback from CTGAN to Gaussian Copula on failure
- Model artifacts saved to `artifacts/models/`

## 7. Temporal Engine Implementation

Statistical temporal modeling with trajectory archetypes:
- Extracts baseline distributions and daily change distributions per variable
- Computes subgroup-specific parameters (diabetes/hypertension)
- Assigns trajectory types: **Stable** (flat trends), **Improving** (downward BP/pain, upward steps), **Worsening** (opposite), **Fluctuating** (sinusoidal oscillation)
- Configurable trajectory distribution per cohort
- Enforces systolic > diastolic BP invariant during generation
- Supports configurable timelines (7-90 days)

## 8. Cohort Conditioning Implementation

Stratified resampling with nested constraint enforcement:
- Generates oversized candidate pool (5x requested)
- Stratifies by age (elderly vs young)
- Adjusts binary columns (diabetes, hypertension) via targeted flipping
- **Conditional constraints**: HTN among diabetic, diabetes among elderly
- Iterates up to 20 attempts to minimize constraint deviation
- Reports requested vs actual percentages with error tracking
- 7 research scenario presets with pre-configured constraint sets

## 9. Privacy Mode Implementation

Three configurable privacy modes:
- **Low**: No filtering, maximum fidelity
- **Balanced**: Moderate near-copy rejection (threshold 0.08, noise scale 0.02)
- **High**: Strict rejection (threshold 0.15, noise scale 0.05)

Privacy filtering applies nearest-neighbor rejection and optional noise injection. Privacy vs Fidelity Explorer compares all three modes on the same cohort.

## 10. Validation Metrics Implemented

- **Numerical**: mean, median, std, min/max, quantiles, KS test, Wasserstein distance
- **Categorical**: frequency comparison, total variation distance
- **Relationships**: correlation matrix comparison, mean absolute difference
- **Longitudinal**: daily mean trends, trend correlation
- **Overall**: fidelity score with documented formula
- **Per-Column Quality Cards**: Individual grades (Excellent: KS < 0.05, Good: < 0.10, Fair: < 0.20, Poor: >= 0.20)
- **Subgroup Fidelity**: Fidelity within diabetic/non-diabetic, hypertensive/non-hypertensive, elderly/non-elderly subgroups

## 11. Privacy Metrics Implemented

- Exact duplicate detection (normalized comparison)
- Nearest-neighbor distance analysis (standardized Euclidean)
- Near-copy flagging (configurable threshold per privacy mode)
- **Real-to-real baseline**: 2nd-nearest-neighbor distances among original data
- **Synth-to-synth distances**: NN distances within synthetic data (diversity check)
- Distance distribution visualization
- Overall screening status (PASSED / REVIEW NEEDED)

## 12. Clinical Plausibility Guardrails

- Bounds checking for all numeric variables against configurable limits
- Binary column validation (diabetes, hypertension must be 0 or 1)
- Systolic > diastolic BP invariant enforcement
- Automated repair functions for profiles and longitudinal data
- Plausibility statistics reported in the Synthetic Cohort page

## 16. Known Limitations

- Not clinically validated; research/demo platform only
- No HIPAA/GDPR compliance evaluation
- No formal differential privacy guarantees
- Demo data relationships are simulation assumptions
- Trajectory archetypes are simulation patterns, not validated disease progression
- Privacy modes provide screening-level protection, not certified anonymization
- CTGAN quality depends on training data size/diversity
- Python 3.14 used; Python 3.11+ recommended for widest SDV compatibility

## 17. Demo Walkthrough

1. Launch FastAPI backend and Next.js frontend using the commands above
2. Data: Load demo dataset (500 patients, 15K longitudinal records)
3. Train: Select Gaussian Copula + Demo mode, train (~1 second)
4. Cohort Builder: Select "Older Diabetic Cohort" preset, set 5000 patients
5. Configure: Adjust HTN-among-diabetic (60%), DM-among-elderly (40%)
6. Trajectories: 40% Stable, 25% Improving, 20% Worsening, 15% Fluctuating
7. Privacy: Select "Balanced" mode
8. Generate: Click "Generate Synthetic Cohort" (~30 seconds)
9. Synthetic Cohort: Verify constraint satisfaction gauges, trajectory distribution
10. Patient Journeys: Select a patient, compare with cohort average
11. Validation: Check fidelity score, per-column quality cards, subgroup fidelity
12. Privacy: Review NN distances with real-to-real baseline context
13. Model Comparison: (Optional) Compare CTGAN vs Gaussian Copula
14. Experiments: Save experiment for future comparison
15. Export: Download complete ZIP with quality report
